# Ansible Web Control

Веб-интерфейс для работы с Ansible-проектами: узлы и группы inventory, запуск и проверка
(`--check`) плейбуков, Autodeploy, создание проектов и ролей, редактор с подсказками,
состояние DHCP/TFTP/ISO, прослушка сети (TCPdump, таблица коммутатора MikroTik по SSH)
и карта сети с автопостроением.

## Требования

- Python 3.7+ и PyYAML (`python3-yaml`).
- Ansible (`ansible-playbook`, `ansible-doc` — для полного справочника подсказок).
- По желанию: `tcpdump` (прослушка), `openssh-client` и `sshpass` (таблица коммутатора по SSH,
  вход по паролю), `traceroute` или `tracepath` (автопостроение карты), `iproute2` (`ip`).

## Запуск

```
python3 web1x.py
```

Интерфейс открывается на `http://<сервер>:8000/`. Адрес, порт, папка проектов и другие
параметры — в `constants.py` или в окне «Настройки» (шестерёнка справа вверху).
Папку проектов можно задать и переменной окружения `ANSIBLE_PROJECTS_ROOT`.

**После обновления файлов перезапустите `web1x.py`** — интерфейс сам предупредит,
если версии интерфейса и сервера не совпадают.

## Файлы приложения

| Файл | Назначение |
|---|---|
| `web1x.py` | HTTP-сервер и вся серверная логика (без сторонних веб-фреймворков) |
| `constants.py` | Настройки: пути, имена файлов, сеть, интервалы опроса |
| `ansible_catalog.py` | Встроенный справочник модулей для подсказок (если нет `ansible-doc`) |
| `logo_mark.png` | Знак приложения с прозрачным фоном: в шапке и иконка вкладки |
| `logo.png` | Прежнее фоновое изображение (адрес `/background`) |
| `public/main.html` | Разметка страницы |
| `public/style.css` | Стили (тёмная и светлая темы) |
| `public/constants.js` | Адреса API и константы интерфейса |
| `public/common.js` | Общие элементы: выбор проекта и объекта, дерево ролей |
| `public/main.js` | Логика интерфейса |
| `public/page.js` | Модальные окна страницы и подтверждение запуска |

Рядом с `web1x.py` сервер сам создаёт служебные папки:
`netmap_data/` (карта сети, найденное прослушкой), `cache/` (справочник `ansible-doc`),
`backups/` (предыдущие версии сохранённых в редакторе файлов), `constants.py.bak`.

## Структура проектов

```
<папка проектов>/<проект>/
├── playbooks/            простой проект: hosts.yml, defaults.yml, ansible.cfg, плейбуки, roles/
├── object/<объект>/      проект с объектами: то же самое — для каждого объекта
└── autodeploy/autodeploy.yml   (необязательно)
```

Новый проект в такой структуре создаёт мастер «Новый проект…» (меню-шестерёнка).

Роли ищутся так же, как их ищет Ansible: `roles/` рядом с плейбуками, пути из `roles_path`
в `ansible.cfg` объекта и `roles/` проекта (учитываются только папки внутри папки проектов).
Autodeploy (`autodeploy/autodeploy.yml`) — свой у каждого проекта, где он есть; в списке
плейбуков он отдельной зелёной строкой (запуск, просмотр, файлы), у проектов без него строки нет.
Его роли ищутся в `autodeploy/roles` и по `roles_path` из `autodeploy/ansible.cfg`. Запускается
на inventory текущего проекта/объекта. Мастер нового проекта может скопировать структуру
Autodeploy из существующего проекта — копия дальше живёт отдельно.

Ссылки на роли понимаются как у Ansible: `infra/nginx` — роль во вложенной папке, `roles/common` —
путь от папки плейбука; зависимости ролей (`dependencies` в `meta/main.yml`) показываются вместе с ними.

Режим «Подсеть» в прослушке проверяет все адреса подсети (пинг и ARP-таблица сервера) и
запоминает занятые отдельно для каждого проекта (`netmap_data/subnets/<проект>.json`): при
заполнении IP узла поле подсвечивается зелёным (свободен) или красным (занят или уже назначен
другому узлу). Подсеть — до /22 (1022 адреса); результат сбрасывается кнопкой «Сбросить».

Удалённые в интерфейсе плейбуки, роли и файлы не стираются, а переносятся в
`backups/<проект>/<объект>/deleted/` рядом с `web1x.py` — их можно вернуть.

## Безопасность

Входа по паролю нет: всё, что умеет интерфейс (запуск плейбуков, правка inventory, ролей
и настроек), доступно любому, кто открыл страницу. Открывайте доступ только из доверенной
сети или поставьте перед приложением обратный прокси с аутентификацией и TLS.

Сервер проверяет все имена и пути: выйти за пределы папки проектов нельзя (в том числе через
символические ссылки), через «плейбук» нельзя прочитать или перезаписать `hosts.yml`
и `ansible.cfg`, в команды ssh/ping не попадают строки, похожие на опции.

История изменений — в `CHANGELOG.md`.
