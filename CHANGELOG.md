# Changelog

## 0.0.13.1 — 2026-09-22

### Changed — NMAP
- Команда сканирования заменена на запрошенную: `sudo nmap --script dhcp-discover --script-args dhcp-discover.requests={all}` — вместо прежнего `nmap -sn <подсеть>`. Это скрипт-обнаружение DHCP-серверов (широковещательный DHCPDISCOVER), а не ping-скан хостов, поэтому и состав данных другой: вместо MAC/IP/производитель список теперь показывает DHCP-сервер, предлагаемый им IP, шлюз и время аренды — то, что реально есть в ответе этого скрипта.
- Под таблицей добавлен «сырой» вывод самого nmap — если результат выглядит пустым или неожиданным (например, не настроен sudo без пароля для nmap, или nmap не установлен на сервере), это будет видно прямо в окне, а не молча «ничего не происходит».
- Команда сканирования вынесена в константу `NMAP_COMMAND` (`constants.py`) — если понадобится другой набор параметров nmap, менять там.

## 0.0.13 — 2026-09-21

### Changed — кнопка «Изменить» в карточке узла
- Кнопка «Изменить» теперь того же синего цвета, что и активная кнопка шаблона в окне «Добавление узла».
- Кнопка объединена с отменой: по клику раскрывается форма параметров (как раньше) и сама кнопка превращается в «Отмена» — отдельная кнопка «Отмена» в подвале карточки убрана за ненадобностью.
- Пока в форме ничего не поменяли, кнопка «Отмена» остаётся синей; как только меняется любое поле, параметр, hwtype или группа — становится красной (предупреждение, что повторный клик отменит и отбросит эти правки).
- Повторный клик по той же кнопке плавно сворачивает форму (та же анимация, что и при открытии), откатывает все несохранённые изменения к исходным значениям без перезагрузки страницы и возвращает подпись «Изменить».

### Added — NMAP: обнаружение узлов в сети
- Кнопка «NMAP» в шапке страницы открывает отдельное окно с кнопками «Включить режим прослушки» / «Отключить».
- Пока режим включён, фоновый поток на сервере раз в 15 секунд сканирует локальные подсети сервера (`nmap -sn`, определяются автоматически через `ip addr`, вручную ничего указывать не нужно) и копит список обнаруженных устройств: MAC-адрес, IP-адрес, производитель (если nmap смог определить), время последнего обнаружения. Список в открытом окне обновляется каждые 3 секунды.
- Определение MAC-адреса — ограничение самого `nmap`: обычно требует прав root; без них устройства могут находиться по IP, но не отображаться в списке (там показываются только пары с определённым MAC).
- Новые эндпоинты: `POST /nmap_start`, `POST /nmap_stop`, `GET /nmap_status`.

## 0.0.12.8 — 2026-09-19

### Added — инфопанель вверху страницы
- Добавлена панель со статусом DHCP и TFTP (`● активен` / `● не активен` / `не удалось проверить`) и сведениями об ISO-образах в `/opt/home/iso` (включая все подпапки): количество файлов, суммарный размер, разворачиваемый список каждого файла с путём, размером и датой изменения.

### Optimized
- `web1x.py`: устранён двойной парсинг `hosts.yml` на каждый запрос `/data` — `template_schemas()` раньше сама заново вызывала `parse_hosts()`, хотя тот же список узлов уже был получен строкой выше. Теперь принимает готовый список необязательным параметром.

## 0.0.12.5 — 2026-09-16

### Fixed
- `public/main.js`: убрано дублирование окна ошибки — функция `api()` сама показывала `alert('Сетевая ошибка: ...')` на ЛЮБУЮ ошибку (включая обычные ответы сервера вроде «узел уже существует»), а затем вызывающий код показывал её ещё раз (например, новое окно ошибки при дубликате узла). Теперь класс снимается сразу по завершении анимации, и в состоянии покоя снова действует запасное «высота не ограничена» — контent всегда виден целиком независимо от того, когда именно подгрузились вложенные данные.

## 0.0.11.6 — 2026-09-11

### Fixed
- `web1x.py` (`add_host`): при добавлении узла в `hosts.yml`, оформленный пустыми строками между хостами, новый узел теперь отделяется от предыдущего пустой строкой — раньше он «прилипал» к последней записи без разделителя. - `web1x.py`: новая функция `set_host_groups()` — принимает желаемый список групп узла, сама вычисляет разницу с текущим членством и добавляет/убирает узел только там, где реально нужно (полная пересборка `hosts.yml` происходит только если узел из какой-то группы действительно удалён).
- `/update_host` теперь принимает необязательное поле `groups` и применяет изменение членства в группах через `set_host_groups()`.

## 0.0.11.5 — 2026-09-11

### Fixed
- `web1x.py`: удалены мёртвые static-маршруты `/hosts_info`, `/hosts_info.js`, `/editor`, `/editor.js` — соответствующих файлов (`hosts_info.html/js`, `editor.html/js`) в `public/` больше нет, страницы были заменены модалкой в `main.html`/`main.js`; переход по этим URL всегда отдавал 404.
- `web1x.py`: удалены неиспользуемые эндпоинты `/files` (GET) и `/save_files` (POST) — фронтенд их не вызывает ни в одном файле.
- `public/main.js`: удалена мёртвая функция `selectPB()` — её роль полностью выполняет `window.togglePlaybookSelection` из `main.html`.

### Optimized
- `web1x.py`: `status_worker()` больше не создаёт новый `ThreadPoolExecutor` на каждую пару «проект × объект» каждые 10 секунд — теперь один пул потоков создаётся один раз и переиспользуется на всё время жизни воркера.
- `web1x.py`: добавлен `/delete_hosts` (POST) — массовое удаление узлов за один проход: один разбор `hosts.yml`, одна финальная очистка пустых групп вместо повторного чтения/записи файла на каждый узел.
- `public/main.js`: `deleteSelectedNodes()` теперь отправляет один запрос `/delete_hosts` со списком узлов вместо последовательной цепочки запросов `/delete_host` (было N чтений/записей `hosts.yml` на N выбранных узлов, стало одно).

### Known inconsistencies (не тронуто в этом проходе)
- `classify_node()` в `web1x.py` классифицирует узел только по количеству параметров, а не по их составу — при совпадающем числе полей возможна неверная классификация шаблона. Исправление требует пересмотра схемы шаблонов и не является безопасной точечной правкой.

## 0.0.11.1 — 2026-09-10

### Fixed
- Исправлен выпадающий фильтр по группам на главной странице: заголовок панели узлов переведён на flex-wrap, поэтому фильтр больше не сжимается до нулевой ширины на узких панелях.
- Убрана некорректная вложенность `<button>` в фильтре групп: кнопка сброса теперь является отдельным элементом управления.
- Исправлена очистка пустых групп в `hosts.yml`: группы разбираются как YAML, вложенные `all.children` также обрабатываются, а удаление выполняется после полного пересчёта структуры.
- `delete_host()` теперь очищает ставшие пустыми группы.
- `add_host()` больше не вставляет лишнюю пустую строку в `all.hosts` при каждом добавлении узла.
- Добавлено удаление группы без удаления самих узлов: backend endpoint `/delete_group` удаляет только блок группы из inventory.
- На главной странице добавлена кнопка «Удалить группу» и модалка выбора группы с подтверждением действия.

### Audit
- Проверена цепочка `hosts.yml` → `inventory_groups()` → `/data` → фильтрация узлов в `main.js`.
- Подтверждено, что фильтр учитывает узлы из вложенных `children`.
- Исправления внесены непосредственно в рабочие `web1x.py`, `public/main.js` и `public/main.html`; временные `web1x-base.py` и `public/main-base.js` удалены.
- Серверный запуск остаётся обычным: `python3 web1x.py`.

### Known inconsistencies
- `hosts_info.js` по-прежнему поддерживает меньше типов шаблонов узлов, чем `main.js`.
- `hosts_info.js` передаёт `node_type` в `/add_host`, хотя серверная функция `add_host()` его не использует.
- `classify_node()` определяет шаблон прежде всего по количеству параметров; это может неверно классифицировать нестандартный inventory с совпадающим количеством полей.

## 0.0.10.8 — 2026-09-09

### Fixed
- Исправлено позиционирование списка объектов: у `.project-context-block` отключён `backdrop-filter`, который создавал containing block для `position: fixed` у кастомного списка объектов и мог ограничивать его позиционирование/слоение областью панели.
- Список объектов остаётся `position: fixed` и продолжает позиционироваться через `getBoundingClientRect()` относительно viewport.

### Fixed
- `web1x.py`: добавлен отсутствовавший static route `/editor.js` — страница `/editor` подключала `<script src="/editor.js">`, но сервер его не отдавал (404), поэтому редактор не работал вообще.
- `public/hosts_info.js`, `public/editor.js`: удалён вызов `renderSummary(...)` — этой функции нет ни в одном файле проекта. Вызов кидал `ReferenceError` и обрывал `load()` раньше времени: на `/hosts_info` список узлов никогда не отрисовывался, на `/editor` не заполнялись `hosts_editor`/`defaults_editor`/`playbook_editor`.
- `web1x.py`: пагинация `/log_new` ломалась после ~1000 записей в логе, потому что `del LOG[:-1000]` сдвигал индексы, а клиент считал их абсолютными. Добавлен `LOG_OFFSET`, через который `start`/`next` теперь считаются в абсолютных координатах независимо от обрезки списка.
- `public/editor.html`: файл на ~91% состоял из нулевых байт (артефакт архивации/выгрузки); содержимое перезаписано без них, разметка не менялась.

### Removed
- `web1x.py`: удалён фактически неиспользуемый `import socket` (в предыдущем changelog заявлялось, что он уже удалён, — на деле нет).

### Known inconsistencies (не тронуто в этом проходе)
- `main.js` (`renderTemplateTabs`) поддерживает создание узла по всем 5 шаблонам из `template_schemas`, а `hosts_info.js` (`getNodeSchemas`) — жёстко только `host`/`md`; узлы типа «СИ» на `/hosts_info` создать нельзя.
- `hosts_info.js` при создании узла отправляет в `/add_host` поле `node_type`, которое сервер не читает.
- `classify_node()` (web1x.py) классифицирует узел по количеству ключей, а не по их составу — при 5 параметрах узел всегда «МД шаблон-2».
