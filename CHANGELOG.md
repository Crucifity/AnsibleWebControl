# Changelog

## 0.0.33 — 2026-10-13

### Added
- **Роли плейбука «ступенькой» в списке.** У плейбуков с двумя и более ролями под строкой плейбука — его роли с флажками (синими; у плейбука — зелёный). Отметка плейбука отмечает все его роли; если отмечена только часть ролей, у плейбука — чёрточка (выбран частично), и при запуске и «Проверке» **выполняются только отмеченные роли**; в подтверждении запуска это видно («только роли: …»), в журнале — заголовок «site.yml (только роли: nginx)». «Выбрать все плейбуки» отмечает плейбуки целиком. Выбирать можно роли из блоков roles: (не include_role).
  Как это работает: перед запуском рядом с плейбуком создаётся временная копия (скрытый файл `.awc-…yml`, в списке не виден), из которой невыбранные роли убраны правкой текста — hosts, vars, !vault и всё остальное не меняются, относительные пути и roles/ работают как у оригинала; после выполнения копия удаляется.
- **Сохранение узла — с выбором**: «Сохранить» (форма остаётся открытой, сохранённое становится исходным — кнопка снова неактивна до новых правок) или «Сохранить и закрыть» (форма сворачивается с анимацией). При переименовании узла — только «Сохранить и закрыть».
- **«Новый плейбук» → узлы (hosts)**: кроме ввода вручную — список «Группы ▾» из hosts.yml (all и группы с числом узлов); несколько групп объединяются через «:» (web:db); all и отдельные группы взаимоисключающие.
- **«Файлы плейбука» → «Переименовать» роль**: папка роли и ссылки на неё во всех плейбуках проекта/объекта (или Autodeploy), в зависимостях (meta) других ролей и в tests роли; можно и в подроль («web/nginx»). Ссылки меняются только там, где это ссылка на роль (roles:, dependencies:, name: в include_role/import_role) — задача с таким же названием не трогается. Предыдущие версии изменённых файлов — в backups/.

### Fixed
- «Новый плейбук» с ролями: список существующих ролей обрезался — последние роли не были видны (раскрывающийся блок был ограничен 260 px). Теперь блок раскрывается на высоту содержимого.
- Временные и прочие скрытые файлы (имя начинается с точки) не показываются в списке плейбуков.

## 0.0.32 — 2026-10-13

### Fixed
- **При открытом окне прослушки `/nmap_status` запрашивался непрерывно** (сотни запросов в секунду — со скоростью ответа сервера). В 0.0.31 смена режима прослушки стала запрашивать статус, а отрисовка статуса сама вызывала «смену режима», чтобы привести переключатель в соответствие с сервером, — получилось кольцо «запрос → отрисовка → запрос». Теперь приведение окна к режиму (`syncNmapModeUi`) запросов не делает, а статус запрашивается один раз только когда режим переключает пользователь; дальше — как раньше, раз в 3 секунды, пока окно открыто.
- В регрессионные проверки добавлен подсчёт частоты запросов: при закрытых окнах `/log_new` — около раза в секунду и ни одного `/nmap_status`; в каждом режиме прослушки — опрос раз в 3 секунды. На 0.0.31 проверка показывает 583–717 запросов за 6 секунд, на 0.0.32 — 2.

## 0.0.31 — 2026-10-13

### Fixed
- **Переменные из общего defaults не предлагались.** Переменные в нём лежат внутри ключа: `defaults:` → `dhcpiface: …`, а подсказки брали только ключи верхнего уровня (то есть один `defaults`). Теперь учитываются вложенные ключи (до трёх уровней) — так, как к ним обращаются в Jinja: `defaults.dhcpiface`, `defaults.dhcp_range.start`. Набор «dhcp» находит `defaults.dhcpiface` и вставляет имя целиком; набор «defaults.» показывает всё, что внутри. Работает для всех источников: общий defaults (файл и папка), group_vars, host_vars, defaults и vars ролей.
- **Окно «Добавить роль»**: флажок «С подролями» залезал на список ролей. Окно больше не меняет размер: вкладки «Существующие» и «Новая роль» плавно сменяют друг друга в одной и той же области.

### Added
- **Новая роль — с выбором частей**: флажками отмечается, что создать — tasks, handlers, defaults, vars, meta, templates, files, tests, README.md (по умолчанию всё).
- **Анимированные флажки** в окнах (мастер, новый плейбук, добавить роль, подтверждения): плавная смена цвета и «прорисовка» галочки.
- **Прослушка — режим «Подсеть»**: подсеть и маска (24 или 255.255.255.0, до /22) → сервер пингует все адреса параллельно и смотрит свою ARP-таблицу (находятся и устройства, которые не отвечают на пинг). Ход сканирования виден, результат — карта подсети: занятые адреса красные, свободные зелёные (щелчок — скопировать адрес), при наведении — MAC и узел inventory. Результат запоминается **для текущего проекта** (`netmap_data/subnets/<проект>.json`) и сбрасывается кнопкой «Сбросить».
- **Подсветка поля IP узла** (добавление и изменение узла): зелёное — адрес свободен по сканированию подсети, красное — занят (с пояснением: ответил при сканировании, MAC) или уже назначен другому узлу этого inventory. Адреса вне сканированной подсети не подсвечиваются; память другого проекта не используется.
- Эндпоинты: `GET /subnet_scan`, `POST /subnet_scan_start`, `/subnet_scan_reset`; `/playbook_roles_add` принимает `parts`.

## 0.0.30 — 2026-10-13

### Added
- **Подсветка синтаксиса в редакторах** (плейбуки, файлы ролей, autodeploy.yml, defaults, ansible.cfg) — в стиле VS Code, для тёмной и светлой темы: YAML (ключи, ключевые слова Ansible, модули по полному имени, строки, числа, true/false, комментарии, теги !vault, якоря, маркер документа), выражения Jinja2 `{{ }}` / `{% %}` в любом месте строки, ansible.cfg (секции, параметры, значения), шаблоны *.j2. Слой подсветки лежит под прозрачным текстом поля ввода — курсор, выделение, Ctrl+Z и подсказки работают как раньше; совпадение проверено посимвольно, в том числе после прокрутки.
- **Окно «Добавить роль»** (вместо поля ввода в окне «Файлы плейбука»): вкладка «Существующие» — роли деревом, с группами и подролями; отметка группы (а с флажком «С подролями» — и роли) отмечает все её подроли; роли, уже подключённые к плейбуку, показаны отмеченными. Вкладка «Новая роль» — имя и, по желанию, подроли: роль становится папкой-группой, в плейбук добавляются «роль/подроль». Несколько ролей добавляются одной правкой плейбука.
- Новая роль создаётся со всеми основными файлами и папками, как у `ansible-galaxy init`: tasks, handlers, defaults, vars, meta, templates, files, **tests** (inventory, test.yml), README.md.

### Changed
- **Редактор плейбука**: окно фиксированной высоты — название сверху и кнопки «Отмена» / «Сохранить» снизу закреплены, прокручивается только текст. Плейбук открывается с начала файла (раньше — прокрученным в конец).
- Из окна «Файлы плейбука» убрана кнопка «Открыть плейбук» (плейбук открывается кнопкой «Просмотр плейбука» в списке).

### Fixed
- **Подсказки не видели переменные из общей папки defaults/.** Файл общих переменных искался только как файл (defaults.yml / defaults.yaml / defaults), а папка `defaults/` пропускалась. Теперь подсказки читают все существующие варианты — и defaults.yml, и все YAML-файлы папки defaults/ — а также `group_vars/` и `host_vars/` (рядом с inventory, плейбуками и в проекте); у каждой переменной видно, из какого файла она. Теги вроде `!vault` чтению не мешают, файл с ошибкой YAML читается по тексту. Кнопка «defaults» при папке открывает `defaults/main.yml`.
- Список подсказок закрывался, если курсор стоял на последней видимой строке редактора (например, в конце длинного файла).

## 0.0.29 — 2026-10-12

### Fixed — подсказки модулей
- **При наборе «ansible.» не предлагались модули ansible.builtin.** Встроенные модули в списке были подписаны коротко («copy»), и полное имя совпадало с набранным только с низким приоритетом, а модули коллекций (ansible.posix, ansible.netcommon, ansible.windows…) подписаны полным именем и шли первыми. В полном справочнике из ansible-doc их сотни, а список был ограничен 60 пунктами — до ansible.builtin дело не доходило.
- Теперь имя модуля дополняется **по частям**, как пространства имён в редакторах кода:
  - «ans» — первым ярлык `ansible.builtin.`, затем `ansible.`;
  - «ansible.» — следующая часть: `ansible.builtin.` (первым), `ansible.posix.`, `ansible.netcommon.` … с числом модулей, под ними — встроенные модули;
  - выбор части имени вставляет её и сразу открывает список её модулей; при наборе с точкой модули подписаны полным именем («ansible.builtin.copy»);
  - короткий набор без точки — как раньше: «co» → `command`, `copy`, затем `community.`.
- Встроенные модули всегда выше модулей коллекций; в списке до 150 пунктов (он прокручивается).

## 0.0.28 — 2026-10-12

### Changed — Autodeploy
- **Autodeploy снова свой у каждого проекта** (в 0.0.27 он ошибочно стал общим: проекты без autodeploy брали чужой). Строка и запуск есть только у проектов, где есть `autodeploy/autodeploy.yml`; список hwtype простого проекта — снова из его собственного autodeploy/hdd.
- **Autodeploy — строкой в списке плейбуков** (первой, в прежнем зелёном цвете) вместо кнопки в шапке панели: «▶ Запустить» (с подтверждением, на отмеченных узлах, с inventory текущего объекта), «Просмотр плейбука» (autodeploy.yml в редакторе с проверкой YAML и подсказками), «Файлы плейбука» (роли Autodeploy с файлами: открыть, создать, удалить; добавить/убрать роль). Поиск по плейбукам находит строку по имени. autodeploy.yml из интерфейса не удаляется.
- Роли Autodeploy — свои: ищутся в `autodeploy/roles`, по `roles_path` из `autodeploy/ansible.cfg` и в `roles/` проекта; новые роли Autodeploy создаются в `autodeploy/roles`. Резервные копии и корзина — в `backups/<проект>/_autodeploy/`.
- **Мастер «Новый проект»: пункт Autodeploy возвращён** — структура берётся из выбранного проекта, у которого Autodeploy есть (в списке — число файлов и объём): папка autodeploy копируется целиком, и дальше это собственный Autodeploy нового проекта, независимый от образца. Без образца — минимальная заготовка (autodeploy.yml, roles/, hdd/).

### Fixed — роли
- **Файлы подролей не показывались.** Ссылка вида `infra/nginx` (роль во вложенной папке `roles/infra/nginx`) обрезалась до `nginx`, такая роль не находилась — и её файлы не отображались. Теперь ссылки на роли понимаются как у Ansible: `infra/nginx` — путь внутри папки ролей, `roles/common` — путь от папки плейбука; имя в окне показывается так, как написано в плейбуке.
- **Зависимости ролей** (`dependencies` в `meta/main.yml`) показываются в окне «Файлы плейбука» под ролью, которая их подключает, — с файлами (Ansible выполняет их перед ролью). «Убрать из плейбука» для них недоступно — они подключены не в плейбуке.
- Пути файлов ролей внутри приложения — вида «роль|путь/в/роли», чтобы роли со «/» в имени не путались с папками внутри роли (старый вид «роль/путь» тоже понимается); в окнах и уведомлениях путь показывается через «/».

## 0.0.27 — 2026-10-12

### Fixed
- **«Файлы плейбука» показывались только у первого плейбука.** Роли искались только в `roles/` объекта, и каждая роль, которой там не было, молча пропускалась — а у плейбуков роли могут лежать там, куда указывает `roles_path` в ansible.cfg (например, в общей папке ролей проекта). Теперь роли ищутся так же, как их ищет Ansible: `roles/` рядом с плейбуками, все пути из `roles_path`, `roles/` проекта (только внутри папки проектов — через roles_path нельзя направить «роль» в системные каталоги).
- Разбор плейбука переписан: все роли каждого плея — строкой, `role:`/`name:` со своими `vars`, `{ role: … }`, списком `[a, b]`; `include_role`/`import_role` в задачах; роли плейбуков из `import_playbook`; путь вида `roles/common` → `common`. Теги вроде `!vault` больше не ломают разбор; если файл не читается как YAML (например, `{{ … }}` без кавычек), роли ищутся по тексту — с пометкой в окне. Ненайденная роль показывается с пометкой и кнопкой «Создать роль», а не исчезает.
- **Autodeploy в проекте с объектами** запускался без inventory объекта — отмеченные узлы не находились. Теперь запуск идёт с inventory и ansible.cfg текущего проекта/объекта.
- **Новый (пустой) проект: у узла был только ansible_host.** Пока в проекте нет узлов, «Добавить узел» предлагает шаблоны параметров из ваших существующих проектов (без повторов) и «Базовый».
- Строки заголовков столбцов («Узел», «Плейбук») сжимались на невысоком экране при длинных списках — списки узлов и плейбуков расходились по высоте. Добавлено в регрессионные проверки.

### Changed
- **Панель «Плейбуки»**: вместо меню «Создать ▾» — кнопки **«Новый плейбук»**, **defaults** и **ansible.cfg**; кнопка **Autodeploy** (прежний зелёный цвет и подтверждение запуска) перенесена сюда из верхней панели.
- **«Новый плейбук»**: выбор «Без ролей» (с примером задачи) или «С ролями» — существующие роли галочками и новые роли «фишками» (создаются со стандартным скелетом). После создания плейбук открывается в редакторе.
- **defaults / ansible.cfg**: если файла нет — создаётся из заготовки, если есть — открывается в редакторе. Перед сохранением проверяется формат: YAML для defaults.yml, INI для ansible.cfg (например, «до первого параметра нужен заголовок секции [defaults]»).
- **«Файлы плейбука» — окно вместо раскрывающегося списка**: все роли плейбука карточками (где лежит роль, в скольких ещё плейбуках используется) с деревом файлов; открыть файл в редакторе, «＋ Новый файл…» в любой папке, удалить файл (× при наведении); **добавить роль** — выбрать существующую или ввести новое имя (роль создаётся и подключается); **убрать роль из плейбука** — по желанию с удалением её файлов (недоступно, если роль используется в других плейбуках); **удалить плейбук**; «Открыть плейбук».
- Добавление и удаление ролей правит плейбук по тексту — комментарии и оформление сохраняются; результат проверяется повторным разбором, при неудаче файл не меняется. Роль, подключённая через include_role, автоматически не убирается — об этом сообщается.
- **Удаление — в корзину**: плейбуки, роли и файлы переносятся в `backups/<проект>/<объект>/deleted/` рядом с web1x.py.
- Autodeploy общий для всех проектов: если у проекта нет своего `autodeploy/autodeploy.yml`, используется файл из любого другого проекта (список hwtype простого проекта — тоже рядом с ним). Из мастера «Новый проект» убран пункт autodeploy — своя заготовка перекрыла бы общий файл.
- Окно «Новая роль» и меню «Создать» удалены (роли создаются в «Новом плейбуке» и в окне «Файлы плейбука»).
- Эндпоинты: `GET /playbook_files`, `POST /playbook_delete`, `/playbook_role_add`, `/playbook_role_remove`, `/role_file_delete`, `/object_file_open`, `/object_file_save`; `/run_autodeploy` принимает `object`.
